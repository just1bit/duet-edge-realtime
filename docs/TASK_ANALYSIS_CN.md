# 基于Duet-EDGE开发近实时集成系统

> 更新日期：2026-08-10

## 1. 任务背景

本任务的主线是：基于 `duet-edge` 项目，开发可持续、连贯运行的近实时集成系统，使伴舞动作以在线形式持续生成，并流式输出火柴人动作/骨架坐标进行动态展示。

现有 Duet-EDGE 已经能够根据主舞动作和音乐生成伴舞动作，也能把多个短窗口拼成长视频。但当前使用的是离线流程：完整动作、音频和预处理特征都提前存在，全部生成、拼接和渲染结束后才得到视频。

近实时集成关注的是另一种运行方式：主舞动作持续到达，系统滚动生成伴舞，输出新增骨架帧。“近实时”允许存在固定延迟，重点是启动后持续、连贯地、不中断地流式输出。开发阶段可以用现有测试数据(动作文件)按帧回放模拟输入，之后再对接摄像头姿态估计或其他动作来源。

> 任务交付重点是可运行的系统链路、模块化接口、稳定的持续输出和可观测的性能表现，而不是模型训练、指标对比或算法研究。

## 2. Duet-EDGE 的现有实现与可复用能力

Duet-EDGE 已提供“主舞动作 + 音乐 → 伴舞动作”的完整离线链路。本任务不需要重新训练或重新设计模型，主要工作是复用现有 checkpoint、动作表示和骨架转换能力，将推理入口、窗口调度和输出方式改造成可持续运行的近实时服务。

模型以 5 秒、30 FPS 的窗口工作，每个窗口共 150 帧：

| 数据 | 形状 | 含义 |
|---|---|---|
| 主舞动作 | `[150, 151]` | 动作条件 |
| Jukebox 音乐特征 | `[150, 4800]` | 音乐条件 |
| 合并条件 | `[150, 4951]` | 主舞与音乐拼接 |
| 伴舞动作 | `[150, 151]` | 生成结果 |

每帧 151 维动作由 4 维脚部接触、3 维根节点位置和 24 个关节的 6D 旋转组成。AIST++ 原始动作是 60 FPS 的根位置与 axis-angle 旋转；`dataset/dance_dataset.py` 会降采样到 30 FPS，转换坐标系和旋转表示，计算脚部接触，并使用 checkpoint 内的统计量归一化。

现有代码中可直接复用的核心环节如下：

1. `model/model.py` 和 `model/diffusion.py` 完成单个 5 秒窗口的条件扩散推理。
2. checkpoint 内的归一化器完成模型输入、输出的尺度转换。
3. 生成结果可转换回 SMPL 根位置与关节旋转。
4. `vis.py` 中的 `SMPLSkeleton.forward()` 可将结果转换为 `[帧数, 24, 3]` 的三维骨架坐标。

工程实现中可通过 CFG 权重选择输入条件：

| 模式 | 条件 |
|---|---|
| `full` | 主舞动作和音乐 |
| `lead` | 只使用主舞动作引导 |
| `music` | 只使用音乐引导 |
| `w0` | 两路引导均关闭 |

首版链路建议使用 `lead` 模式，只接入主舞动作，以避免实时 Jukebox 特征提取阻塞主流程；系统稳定后再增加音乐条件。这是降低集成复杂度的实施顺序，不改变模型接口。

### 2.1 现有长动作流程为什么不能直接用于在线运行

Duet-EDGE 一次只生成 5 秒。长动作使用 2.5 秒步长，相邻窗口重叠 75 帧。

`model/diffusion.py` 中的 `long_ddim_sample()` 会一次接收整段的全部窗口。在每个 DDIM 去噪步骤中，后一个窗口的前 75 帧会复制前一个窗口的后 75 帧，使相邻窗口共享重叠区。

采样结束后，`render.py::_stitch_and_fk()` 还会校准根节点位置，用 raised-cosine 权重融合重叠位置，用四元数 slerp 融合重叠关节旋转，最后执行正向运动学并渲染视频。

该实现要求开始推理前获得整段输入，并让所有窗口同时参与采样。窗口数量增长时，显存和处理时间也随之增长，因此不能直接用于持续输入。近实时版本需要改为固定大小的滑动缓冲区，每次只生成一个新窗口，并仅保存跨窗口连续所需的重叠帧和状态。

## 3. 现有演示的工程参考与改造重点

`ep1800_cfg_sweep/` 验证了 checkpoint 加载、条件配置、长窗口生成、骨架转换和视频渲染能够完整运行。与本任务直接相关的代码入口包括：

- `run_ep1800_cfg_sweep.sh`
- `eval/run_ep1800_cfg_sweep.py`
- `render.py`
- `model/diffusion.py`
- `vis.py`

现有演示采用完整文件输入、整段采样和 mp4 输出，只能作为离线基线，不能直接作为近实时程序。可保留模型加载、单窗推理、反归一化和正向运动学，其余部分需要替换为以下工程组件：

1. **输入适配器**：按 30 FPS 接收或回放主舞帧，转换成模型要求的 151 维表示。
2. **窗口缓冲器**：维护最近 150 帧，并按设定步长触发一次推理。
3. **增量推理器**：常驻加载模型，每次只处理当前窗口，避免重复初始化和历史数据累积。
4. **连续性处理器**：保存上一窗口的重叠区，对新窗口执行约束、对齐和融合。
5. **输出通道**：将新增的三维骨架帧写入队列或 WebSocket；展示端独立消费，避免渲染阻塞推理。

首版建议先完成“动作文件按帧回放 → lead-only 单窗推理 → 骨架坐标流式输出 → 简单动态展示”的闭环，再依次加入跨窗融合、性能优化、摄像头输入和音乐条件。

实现时需要重点处理以下约束：

- 单窗生成耗时必须小于窗口触发间隔，否则需要调整步长、DDIM 步数或计算资源。
- 逐窗推理不再共享整段扩散状态，必须显式保存和融合重叠区，避免边界跳变。
- CFG 应只执行实际启用的条件分支，减少无效计算。
- 摄像头关键点不能直接输入模型，后续接入时需要单独实现 SMPL 映射、尺度统一和旋转估计。
- 运行时应记录输入帧率、缓冲积压、单窗耗时、输出延迟和异常恢复情况，便于定位链路瓶颈。

## 4. 目录内容概览

| 路径 | 内容与作用 |
|---|---|
| `Real-Time Full-body Interaction with AI Dance Models, Responsiveness to Contemporary Dance.pdf` | 实时全身交互相关论文 |
| `data+checkpoint/train-1800.pt` | 约 1.1 GB 的 Duet-EDGE checkpoint，包含权重和动作归一化器 |
| `data+checkpoint/aist_plusplus_final.7z` | AIST++ 动作与音频数据压缩包 |
| `duet-edge/EDGE.py` | 组装网络、扩散器和 SMPL 骨架，加载 checkpoint |
| `duet-edge/model/model.py` | Transformer 和多条件 CFG |
| `duet-edge/model/diffusion.py` | DDIM、长窗口联合采样和扩散训练逻辑 |
| `duet-edge/dataset/dance_dataset.py` | 动作预处理、151 维表示、归一化和双人配对 |
| `duet-edge/data/slice.py` | 将完整动作和音频切成离线窗口 |
| `duet-edge/test.py` | 面向完整文件和切片目录的离线推理入口 |
| `duet-edge/render.py` | 长窗口选择、拼接和正向运动学 |
| `duet-edge/vis.py` | SMPL 24 关节骨架与视频渲染 |
| `duet-edge/eval/` | PFC、LMA、CFG sweep 和相关评测报告 |
| `duet-edge/prepare_sfm_demo.py` | 准备自由编舞演示数据 |
| `duet-edge/run_*.sh` | 服务器和 Slurm 环境中的训练、评测、渲染命令 |
| `duet-edge/SMPL-to-FBX/` | 可选的 SMPL 动作到 FBX 转换工具 |
| `ep1800_cfg_sweep/` | epoch 1800 不同 CFG 设置下生成的离线视频和说明 |

与目录内容相关的几个背景点：

- 当前 checkpoint 位于 `data+checkpoint/`，部分服务器脚本记录的默认路径则是 `runs/train/exp9/weights/train-1800.pt`。
- `motions/` 中的原始根位置带有 AIST++ 尺度信息；`motions_sliced/` 中的位置已经缩放。
- 现有切片数据通常采用 0.5 秒步长；长视频拼接每隔 5 个切片取一个，即使用 2.5 秒步长。
- 由于原始 EDGE 的目录设计，`data/test/` 被训练循环用于过程监控，仓库中的独立报告主要使用 `data/val/`。
- 单人 EDGE 使用 4800 维音乐条件，Duet-EDGE 使用 4951 维主舞与音乐联合条件，两类 checkpoint 的条件结构不同。
- `ep1800_cfg_sweep/` 是离线演示产物，其中 sFM 没有真实伴舞参考。
